# /dev — один цикл разработки second_brain

Порт скилла `/dev` из GrowthProducer, адаптированный под этот репозиторий:
здесь нет `spec/<module>.md` и Python-пакета — источники правды это `ТЗ.md`
(технический слой), `PRD.md` (продуктовый), `Promts/*.md` (поведение слоёв)
и `tools/second-brain-mcp/` (код инструментов).

## Режим

- **routine** — нет аргументов / «ок» / «go» / «продолжай» / эмодзи. Молча,
  без `AskUserQuestion`, задачи `[BLOCKED]` пропускаются.
- **interactive** — осмысленное сообщение владельца. Сначала ответить на него;
  можно задать `AskUserQuestion`, чтобы снять блокер.

Сомневаешься → routine.

## Вывод

За цикл наружу — одна строка прогресса (шаг 6). Всё остальное живёт в
коммитах.

## Жёсткие правила

1. **Ветка.** Работать в ветке, указанной задачей/окружением; `main` не
   трогать напрямую, force-push запрещён.
2. **Doc-driven.** `TODO.md` + `DEV_PLAN.md` → выбрать задачу → прочитать
   ОДИН релевантный документ (`ТЗ.md` § нужного слоя, `PRD.md` или
   `Promts/<слой>.md`) → если меняется дизайн, сначала правится документ,
   потом код.
3. **Граф.** Есть `graphify-out/graph.json` → искать по коду через
   `graphify query "<вопрос>"`, а не сплошным чтением (`CLAUDE.md`).
   После правок кода — `graphify update .`.
4. **Гранулярные коммиты.** Тема ≤72 символов, императив. В теле — id задач
   из `TODO.md`, какой документ обновлён, что осталось.
5. **TODO ↔ DONE.** Закрытая задача **переезжает** в `DONE.md` (дата + строка).
   В `TODO.md` к концу сессии — только незакрытое.
6. **`[BLOCKED]` не снимать**, пока причина реально не снята.
7. **Тесты обязательны** для детерминированной логики MCP-сервера
   (vault, frontmatter, выбор модели, цена). Не писать тесты на обёртки
   вокруг сети и на логирование.
8. **Никогда** `--no-verify`, никогда force-push, никаких названий моделей
   в коммитах/PR/коде.
9. Разрушительные действия (снос тома, wipe памяти gbrain, удаление
   зависимостей) — только с подтверждения владельца.

## Цикл

### Шаг 1 — сориентироваться

`git fetch origin`, актуализировать рабочую ветку от `origin/main`.
Конфликт → откатить, записать `[BLOCKED: конфликт слияния в <файл>]`, стоп.
Прочитать `TODO.md` и `DEV_PLAN.md`. Больше ничего на этом шаге.

### Шаг 2 — выбрать задачу

Первая по порядку задача, которая: не `[x]`, не `[~]` из живого цикла, не
`[BLOCKED]` (в routine), и все её предпосылки по `DEV_PLAN.md` закрыты.
Одна задача за цикл. Пометить `[~]` и запушить эту пометку сразу.
Нечего брать → стоп, вывести «нет актуальных задач; блокеры: <список>».

### Шаг 3 — прочитать документ

ОДИН документ по задаче. Не хватает детали → читать исходник, а не второй
документ.

### Шаг 4 — обновить документ (если дизайн изменился)

Правка документа — отдельным коммитом, до кода.

### Шаг 5 — реализовать и проверить

Код: ESM, Node/bun, без лишних зависимостей; MCP-инструменты объявляются в
`tools/second-brain-mcp/src/index.js`, логика — в `src/lib/<модуль>.js`.
Промты — в `Promts/`, собираются в `SOUL.md` энтрипойнтом (SOUL.md руками не
править). Перед коммитом:

```bash
make test        # bun test + smoke-проверка списка инструментов
bash -n docker/entrypoint.sh
```

Правил Docker/энтрипойнта касаешься — прогнать и `make build`.

### Шаг 6 — коммит, пуш, снимок прогресса

Коммит на задачу (или каждые ~3 правки файлов), затем
`git push -u origin <ветка>`; при сетевой ошибке ретраи 2/4/8/16 с.

Перед пушем перенести закрытую задачу в `DONE.md`.

Одна строка наружу:

```
M3: X/N | Инфраструктура: X/N | Блокеры: <кол-во>
```

### Шаг 7 — продолжить или остановиться

Продолжать со шага 2, если осталось ≥30% бюджета контекста, прошлая задача
закрыта чисто и следующую можно назвать без перечитывания.

Стоп: блокер (пометить `[BLOCKED]`, запушить), нужно разрушительное решение
(interactive → `AskUserQuestion`; routine → `[BLOCKED]`), мало контекста.

### Шаг 8 — PR (только в конце цикла)

После финального пуша убедиться, что для ветки есть открытый PR на `main`;
нет — создать. Не перечитывать состояние PR, не обновлять описание каждый
цикл, не читать комментарии — этим занимается отдельная подписка.

## Не делать

- Читать несколько документов «на всякий случай».
- Брать пачку «сделаю 3.1–4.2»: одна задача → закрыть → запушить → следующая.
- Полировать несвязанный код, объяснять код комментариями вместо документа.
- Править `SOUL.md` (генерируется) и файлы vault-а в обход MCP-инструментов.
- Ходить в сеть в тестах: каталог моделей и shir-man подменяются `fetchImpl`.

## Типовые сбои

- Пуш не прошёл после 4 ретраев → закоммитить локально, записать причину, стоп.
- Тест падает и не чинится → `[~]` + строка `pending:`, запушить, стоп.
- Нет ключа/переменной → добавить в `env.example`, `[BLOCKED: <VAR> не задан]`.
- Документ противоречит коду → чинить противоречие: код прав → править
  документ; иначе `[BLOCKED]`.
